## 1. The 17 Recovered "Forgotten" Hardware, Kernel & RF Discoveries

The following 17 confirmed discoveries were established between Stages 1 and 40 or within deep subagent research lanes, and are preserved here as canonical ground truth:

### 1. Mandatory `hostapd` / `wpa_supplicant` OOM Protection on 64 MB RAM (`AR9342`) (`CONFIRMED`)
- **Discovery**: Setting `echo -900 > /proc/$(pidof hostapd)/oom_score_adj` is **mandatory** on all 64 MB RAM `AR9342` boards (`LAP-120`, `NanoStation 5AC Loco`, `LiteBeam 5AC Gen2`, `PowerBeam 5AC Gen2`).
- **Physical Consequence**: Under combined heavy bulk TCP + UDP IPTV/VoIP load, free RAM drops to `~14–16 MB`. The Linux kernel OOM-killer identifies `hostapd` as the highest badness score process and kills it, dropping the entire wireless sector. Setting `-900` eliminates this crash completely.
- **Attribution**: `Linux` memory management.

### 2. `mac80211` FQ Memory Ceiling Panic Prevention (`CONFIRMED`)
- **Discovery**: `/sys/kernel/debug/ieee80211/phy0/aqm/fq_memory_limit` defaults to `16,777,216` B (`16 MB`)—fully 25% of the total `64 MB` RAM on `AR9342`.
- **Physical Consequence**: During bursty micro-congestion, `fq_codel` skb buffers consume the entire remaining free memory, triggering catastrophic kernel panics (`do_page_fault` / `out of memory`). It **must be clamped to `4,194,304` B (`4 MB`)**.
- **Attribution**: `mac80211` / `ath79` memory constraint.

### 3. `ETH_P_TEB` (`0x6558`) Decapsulation Patch in `mac80211.ko` (`CONFIRMED`)
- **Discovery**: Stock `airOS 8` CPEs operating in 4-address WDS bridge mode send Ethernet frames encapsulated with an inner `0x6558` (`ETH_P_TEB` — Transparent Ethernet Bridging) protocol tag.
- **Physical Consequence**: Standard upstream OpenWrt Linux 6.6 `mac80211.ko` fails to decapsulate `0x6558` headers, dropping or mangling bridged Ethernet frames from stock CPEs. A 71-byte patch in `ieee80211_data_to_8023_exthdr` (`mac80211.ko` SHA-256 `19a8fde6...`) strips this header, enabling seamless transparent WDS bridging.
- **Attribution**: `mac80211` / `proprietary airMAX module`.

### 4. Two-Stage Vendor IE Withdrawal ("Step 1C") for 100% AP-Side Zero-Touch Interop (`CONFIRMED`)
- **Discovery** (Subagents `d28c55ce` & `7455b1cc`): A stock `airOS 8` CPE (`allow_80211=0`) enforces two gates: Gate 1 (`scan_list` via `giwscan_cb`) and Gate 2 (`sta_list` via `ubnt_poll_host_is_ap_valid`). In `ubnt_poll_host_on_beacon_rx`, `step=0` removes the AP `bssid` from `sta_list` if Beacons lack the Ubiquiti Vendor IE (`0xdd`, OUI `00:15:6d` / `00:27:22`, `msg_type=1`).
- **Physical Consequence**: If an OpenWrt AP advertises the IE during discovery/Auth Req, and then withdraws it (`SET vendor_elements ""` + `UPDATE_BEACON`), `ubnt_poll_host_on_assoc_req_tx` (`0x92bc`) logs `"Associating with normal AP"`, calls `ubnt_poll_host_ht_comm_tx(handle, msg_type=12/13, mode=0)` disabling TDMA polling in the CPE's QCA988x radio firmware (`WMI 0x901f`), and associations proceed in pure CSMA/CA without touching the CPE.
- **Attribution**: `proprietary airMAX module` (`umac.ko` / `ubnt_poll_host.ko`).

### 5. `iperf3 -J` Fatal SIGSEGV on Big-Endian MIPS (`CONFIRMED`)
- **Discovery**: Running `iperf3` with the `-J` (JSON output) flag on MIPS big-endian targets (`AR9342`, `QCA9558`) causes a fatal `SIGSEGV` segmentation fault in `cJSON_PrintUnformatted()` (`libiperf.so.0.0.0` / `cJSON 1.7.15`).
- **Operational Rule**: All physical benchmarks must invoke plain-text `iperf3` (`-c <ip> -t 8 -P 2`) without `-J`.
- **Attribution**: `Linux` userspace (`cJSON` big-endian MIPS32 ABI bug).

### 7. airOS 8 Persistence Mechanics: `rc.poststart` vs `cron` (`CONFIRMED`)
- **Discovery** (Subagent `5ad55eab`): On stock `airOS 8`, `/usr/etc/rc.d/rc.funcs` only executes `/etc/persistent/rc.poststart` if the marker `/etc/poststart` exists. `/sbin/ubntconf` only creates this marker on `-cs` (custom script) builds, while `/sbin/uav` removes custom `rc.*` files on non-`-cs` builds.
- **Universal Fix**: `cron.status=enabled` and `cron.1.job.1.cmd=...` in `/tmp/system.cfg` is parsed natively by `ubntconf` on **all builds** (`-cs` and stock release). Combining `cron` `@reboot` / periodic check with `/etc/persistent/` is the only 100% universal persistence mechanism across non-`-cs` stock `airOS 8` units.
- **Attribution**: `proprietary airMAX module` (`ubntconf` / `uav`).
