## Testedness and cross references

Absence from a Champion profile is not evidence that a control is untested. The
miner separately extracts literal control/value references from frozen stage JSON
and Champion declarations, keeping JSON pointers and source paths. Numeric scalar
readbacks and integer-vector recipes are preserved without evaluating shell text.
Recipe strings, declared Champion settings and saved reported settings are distinct.
automatic_execution_allowed=false does not erase saved historical measurements.

This cutoff contains 590 references: 20 Champion-declared settings, 189 recipe
intentions, 312 numeric receipt mentions, 24 saved reported settings and 45 path
mentions. These are reference counts, not independent experiments. Twenty-nine
control declarations have reported overlap; 116 have no matching reference in this
bounded corpus. Neither count establishes universal testedness. A matching value
does not establish exact build, role, true effective state or causal improvement.
Older nested bench trees and external experiments are not exhaustively joined.

Vault cross references are line-numbered lexical topic overlap only. At least two
candidate topic terms must occur on a line; stored notes may repeat a claim without
authenticating the cited paper. paper_claim_verified and hardware_transfer_proven
remain false. This task did not manufacture literature evidence or query radios.

Conflicts are retained: Stage24 and Stage25 reuse M3/M5 for different mechanisms;
legacy target subtype routing disagrees with the later reviewed consumer model;
M4 power_Balance_adjust/dl_ul_Symbol_adjust aliases are absent from the held AP57
module-parameter list and cannot become new writable controls by renaming.
