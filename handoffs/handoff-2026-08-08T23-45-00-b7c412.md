## 2. Where the project actually is

**Decisions** (`docs/DECISIONS.md`, D-0001…D-0005): OpenWrt 24.10.4 / ath79-generic
(Linux **6.6.110**) is the custom-firmware vehicle. airOS runs Linux **2.6.32** — the nine-year
kernel gap is where every technique the research corpus identified actually lives.

**Hardware — FMX-0001 DONE, Grade A** (`docs/HARDWARE_MATRIX.md`). Six units read live:
all QCA988x Wave 1; five on AR934x @535 MHz/64 MB; Rocket Prism 5AC on QCA955x @720 MHz (the
only unit with real CPU headroom).

**Lab unit:** LiteAP AC / LAP-120, `sysid 0xe8e5`, airOS 8.5.12, **0 clients**, factory-default
creds, management over `br0`/`eth0` so radio changes cannot cut SSH. Verified restored to
baseline. OpenWrt `ubnt_lap-120` factory + sysupgrade images are downloaded and **SHA-256
verified** in `firmware/openwrt/`. **Not flashed.**

**What we know about airMAX** (`knowledge/RADIO_FIRMWARE_ANALYSIS.md`, `AIRMAX_ARCHITECTURE.md`):
three layers — `ubnt_poll_host.ko` (control plane, **zero** scheduling primitives across 150
functions), `ol_ath`/`umac.ko` (QCA vendor offload driver, *not* ath10k), and **custom QCA988x
radio firmware** containing `ubnt-poll` code absent from stock QCA. The scheduler is in
firmware. Radio firmware has been frozen since ~2017 (8.7.22 ≡ 8.7.25 byte-identical), which
confirms the project's motivating premise: Ubiquiti abandoned this silicon.

**Deployment constraint** (`mm-4760`): a custom-firmware CPE **cannot** associate with a stock
airMAX AP. airMAX is negotiated via proprietary IEs and both ends load role-specific radio
firmware. **Both ends must be flashed — the sector is the unit of deployment and rollback.**
Size the lab as a sector, not a link.

## 3. The two blockers

**A. Flash + recovery method for the LAP-120 — gates everything physical.**
The OpenWrt factory image carries magic `OPEN`; airOS `fwupdate` validates signatures. The
OpenWrt wiki for the sibling NanoStation AC documents patching `ubntbox`/`fwupdate.real` on a
specific airOS version. Whether the LAP-120 on 8.5.12 needs that, a different patch, or accepts
TFTP directly is **UNKNOWN**. Resolve by reading the `ubnt_lap-120` OpenWrt device page
**through a browser** — openwrt.org serves a bot challenge to plain HTTP.
Then run **FMX-0002 (recovery qualification) before the first write.** Pre-flash checklist is in
`docs/EXPERIMENTS.md`. Never write `u-boot`, `u-boot-env`, or `EEPROM`.

**B. A second radio.** One LiteBeam 5AC Gen2 or NanoStation 5AC loco on the bench. Without a
link, FMX-0003 onward and all eight Stage 4 criteria are unmeasurable. Operator action.

## 4. Two live threads

**The `umac` source hunt.** `umac.ko` ships **`Dual BSD/GPL`** while every other Atheros module
is Proprietary — so a source-publication obligation exists. If the 10.1/10.2 `ol_ath` source
surfaces, FuturaMAX can be built in Ubiquiti's own architectural slot instead of around
ath10k's narrower surface. **Genuinely different projects; one search decides which.**

- Ruled out with evidence: CodeLinaro `qca-wifi-10.2` feed (packaging; internal Gerrit),
  `qsdk_wifi_qca-wifi-oss` (cloned — no AR9888), `kmeaw/netgear-r7500-openwrt` (packaging),
  `Arx-Alliance/Arx-Kamikaze` (**does not exist**), `CodeFetch/Ubiquiti-UBNT-airOS` (stock
  OpenWrt tree — **Ubiquiti's GPL drop excludes the driver**).
- **LIVE:** `SVoxel/R7500` (218 MB). Its manifest states `IPQ8064 + QCA8337 + QT2518 +
  **QCA9880**` — our chip, right era, vendor GPL lineage. Needs a shallow clone and a grep for
  `umac`, `ol_ath`, `AR9888`, `config.wlan`. **My API probes hit GitHub's unauthenticated rate
  limit — the directories are real; treat as unresolved, not dead.**
- A ChatGPT run is mid-flight at `https://chatgpt.com/c/6a77b935-6bc0-83e9-b40f-ed2006f2e18a`
  reporting "three public trees contain an actual `qca/src/qca-wifi/offload/hw/AR9888/`". May
  be the same finding from another direction. **Verify every URL it returns — half of the
  previous LLM research was false.**
- Assignable prompt: `research/RESEARCHER_PROMPT_qca_umac_source.md`.

**The airMAX IE — best unblocked lead.** airMAX advertises via vendor IE **element ID 221,
OUI `00:15:6D`** in beacons. Independently testable *right now*: card in monitor mode near any
AP, capture beacons, decode vendor IEs. Corroborates `proto_insert_ie`/`proto_parse_ie` in
`ubnt_poll_host`. Needs no source drop, no vendor, no permission — and understanding the
existing AP↔CPE negotiation is groundwork a custom firmware needs regardless.
