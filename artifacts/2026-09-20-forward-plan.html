4 · Phase B — FMX-0011: reproducible build with spectral ME

Why a full buildroot and not the ImageBuilder: spectral does select KERNEL_RELAY, and CONFIG_RELAY is off in the stock 24.10 kernel. That is a kernel change; ImageBuilder only assembles prebuilt packages.

git clone -b v24.10.4 --depth 1 https://git.openwrt.org/openwrt/openwrt.git futuramax-openwrt
cd futuramax-openwrt && ./scripts/feeds update -a && ./scripts/feeds install -a

cat > .config <<'EOF'
CONFIG_TARGET_ath79=y
CONFIG_TARGET_ath79_generic=y
CONFIG_TARGET_MULTI_PROFILE=y
CONFIG_TARGET_DEVICE_ath79_generic_DEVICE_ubnt_lap-120=y
CONFIG_TARGET_DEVICE_ath79_generic_DEVICE_ubnt_litebeam-ac-gen2=y
CONFIG_PACKAGE_MAC80211_DEBUGFS=y
CONFIG_PACKAGE_ATH_DEBUG=y        # required by ATH_SPECTRAL
CONFIG_PACKAGE_ATH_SPECTRAL=y     # -> ATH10K_SPECTRAL + KERNEL_RELAY
EOF
make defconfig
./scripts/diffconfig.sh > futuramax.diffconfig      # this file IS the reproducible build
make download -j8 && make -j6 2>&1 | tee build.log

Exit checks before any flash:

  • Build log shows CONFIG_ATH10K_SPECTRAL=y for ath10k-ct and CONFIG_RELAY=y in the kernel config
  • Extract kmod-ath10k-ct from the output and strings ath10k_core.ko | grep spectral_scan — the symbols must be there
  • Record: git tag, futuramax.diffconfig, sha256 of both sysupgrade images, kernel version, CT firmware file name (must still be …lede.022) → firmware/build/MANIFEST.md
Side effect: this is the AGENTS.md §11 P0 "reproducible build system". Commit the diffconfig and the manifest and it is done.

8 · Phase F — The autoresearch bench (D-0009) ME

Built after E2 exists, because the evaluator must be validated against a real baseline before any agent is allowed to score against it.

  1. bench/ (immutable): topology.yaml, traffic scripts, telemetry collector (peer_stats, fw_stats, pktlog, spectral), evaluator (lexicographic: p99 → p95 → fairness → goodput/MHz → retry airtime → aggregate), safety (validity gates + rollback via the proven recovery).
  2. A/B/A/B runner writing runs/<id>/ and results.tsv, with the full RF/driver/env fingerprint per run.
  3. policy/ gen-1 knobs only (pacing/FQ, htt_max_amsdu_ampdu, AQL point, spectral-driven channel policy, later ratemask-CT).
  4. Only then: let an agent propose changes. Never set_rate_override as per-CPE control; never per-peer TX power or arbitrary retries in gen 1.
